# امنیت هورمند: راه‌اندازی، چک‌لیست نصب و نگه‌داری

این فایل برای کسی است که هورمند را روی سرور یک سازمان نصب یا نگه‌داری می‌کند.

## ۱. HTTPS (رمزگذاری ارتباط)

هورمند خودش TLS ندارد؛ جلوی آن Caddy می‌نشیند و گواهی رایگان Let's Encrypt می‌گیرد.

```bash
# پیش‌نیاز: رکورد A دامنه روی IP عمومی سرور، پورت ۸۰ و ۴۴۳ روتر به سرور
sudo bash https.sh office.example.ir            # HTTPS روی ۴۴۳
sudo bash https.sh office.example.ir 8443       # HTTPS روی پورت دیگر
HARDEN=1 sudo bash https.sh office.example.ir   # + قفل‌کردن (پایین‌تر توضیح داده شده)
```

- هدر `Strict-Transport-Security` را خود برنامه روی پاسخ‌های HTTPS می‌گذارد.
- گزینهٔ `HARDEN=1` (یا دستی در `.env`: `BIND_ADDR=127.0.0.1` و `FORCE_HTTPS=1`) پورت ساده را به روی شبکه می‌بندد و هر درخواست HTTP را به HTTPS می‌فرستد.
  **پیش از آن** برنامهٔ سپیدار و آپلود ضبط مکالمهٔ سانترال را روی آدرس `https://` تنظیم کنید، وگرنه قطع می‌شوند.

## ۲. رازها و کلیدها

| مورد | کجا ساخته می‌شود | نکته |
|---|---|---|
| `JWT_SECRET`، `DB_PASSWORD`، `ADMIN_PASSWORD` | `install.sh` برای هر نصب، تصادفی و جدا | فایل `.env` با دسترسی `600`؛ هرگز در git نیست |
| کلید VAPID (اعلان موبایل) | هنگام اولین اجرا در پایگاه داده هر نصب | بین مشتری‌ها مشترک نیست |
| کلید آپلود ضبط مکالمه | هنگام اولین اجرا (یا `VOIP_RECORDING_KEY`) | حداقل ۱۶ کاراکتر |
| کلید API برنامه‌های بیرونی | مدیر در کنسول می‌سازد | فقط هش آن نگه‌داری می‌شود |
| راز ورود دو مرحله‌ای | با خود کاربر | رمزنگاری‌شده (AES-GCM با کلید برگرفته از `JWT_SECRET`) در پایگاه داده |

برنامه اگر `ADMIN_PASSWORD` ضعیف یا نمونه (`change-me`) باشد، در نصب تازه راه نمی‌افتد.

**تغییر `JWT_SECRET`** همهٔ کاربران را یک بار از سیستم بیرون می‌اندازد و **راز ورود دو مرحله‌ای همه را نامعتبر می‌کند** (باید دوباره روشن شود). پس فقط هنگام لو رفتن آن را عوض کنید.

## ۳. ورود دو مرحله‌ای

هر کاربر از آیکن کلید (بالای صفحه) آن را روشن می‌کند. برای مدیران توصیه کنید.
اگر کسی هم گوشی و هم کدهای بازیابی را گم کرد:

- مدیر کل: `POST /api/auth/2fa/reset` با `{ "userId": "..." }` (یا از رابط، وقتی افزوده شد)
- یا روی سرور: `docker compose exec db psql -U automation -c "DELETE FROM user_2fa WHERE user_id='ID-کاربر'"`

## ۴. پشتیبان‌گیری

- هر شب نسخهٔ کامل پایگاه داده در پوشهٔ `backups/` ساخته می‌شود؛ این پوشه بیرون از ریشهٔ وب است و فقط مدیر ارشد از طریق کنسول می‌تواند دانلود کند.
- فایل‌های پشتیبان **رمزنگاری نشده‌اند**. دیسک سرور (BitLocker/LUKS) یا مقصد شبکه‌ای را رمزنگاری کنید، یا پوشه را با ابزاری مثل `age`/`gpg` رمزنگاری و بیرون ببرید.
- **حداقل هر سه ماه یک بار بازیابی را آزمایش کنید** (روی سرور آزمایشی): `./restore.sh backups/FILE.dump`.
- رمز پوشهٔ شبکه‌ای (SMB) و کلیدهای پنل پیامک/هوش مصنوعی/ربات در جدول `settings` پایگاه داده نگه‌داری می‌شوند؛ پایگاه داده به شبکه باز نیست، اما از نسخهٔ پشتیبان این رازها هم قابل‌خواندن‌اند. نسخه‌ها را مثل رمز نگه دارید.

## ۵. چک‌لیست پیش از هر نصب تازه

1. سرور تازه و به‌روز؛ فقط پورت‌های ۸۰ و ۴۴۳ (و SSH از آدرس‌های مجاز) باز باشد؛ پورت پایگاه داده (۵۴۳۲) به بیرون باز **نباشد** (در `docker-compose.yml` منتشر نمی‌شود).
2. `install.sh` را اجرا کنید (رازهای تصادفی و یکتا می‌سازد). `.env` از یک نصب به نصب دیگر کپی **نشود**.
3. رمز مدیر ساخته‌شده را پس از اولین ورود عوض کنید و ورود دو مرحله‌ای مدیر را روشن کنید.
4. `sudo bash https.sh <دامنه>` و بعد، پس از تنظیم برنامه‌های جانبی روی https، `HARDEN=1`.
5. در مرورگر `https://دامنه` را باز کنید: قفل سبز، و بالای `Network → Response Headers` باید `Content-Security-Policy` و `Strict-Transport-Security` دیده شود.
6. بررسی کنید `https://دامنه/.env` و `https://دامنه/.git/config` جواب ۴۰۴ می‌دهند.
7. پشتیبان دستی بگیرید و یک بار بازیابی را آزمایش کنید.
8. نام و دسترسی کاربران را در «جدول مجوزها» مرور کنید: هر نفر فقط آنچه لازم دارد؛ کاربران ترک‌کار را غیرفعال کنید (نشست‌هایشان هم بسته می‌شود).
9. کلیدهای پنل پیامک، هوش مصنوعی و ربات‌ها را فقط در «تنظیمات» وارد کنید، نه در پیام‌رسان یا ایمیل.
10. تاریخ تنظیم‌شدهٔ بعدی: به‌روزرسانی هورمند (`auto-update.sh`) و `docker compose pull` برای ایمیج پایگاه داده.

## ۶. وقتی کلیدی لو رفت

| لو رفته | کار |
|---|---|
| رمز یک کاربر | رمز تازه توسط مدیر؛ همهٔ نشست‌هایش بسته می‌شود |
| `JWT_SECRET` | مقدار تازهٔ تصادفی در `.env` و `docker compose up -d`؛ همه دوباره وارد می‌شوند؛ ورود دو مرحله‌ای‌ها دوباره روشن شود |
| `DB_PASSWORD` | `ALTER USER automation PASSWORD '...'` + `.env` + راه‌اندازی دوباره |
| کلید API هورمند (برنامهٔ بیرونی) | در کنسول حذف و تازه بسازید |
| کلید پنل پیامک (کاوه‌نگار)، هوش مصنوعی (togpt)، توکن ربات بله/تلگرام | از پنل همان سرویس باطل و کلید تازه در تنظیمات هورمند وارد کنید |
| رمز AMI سانترال | در سانترال عوض و در `.env` (`AMI_SECRET`) به‌روز کنید |
| کلید ضبط مکالمه | فایل `.key` در پوشهٔ ضبط‌ها را پاک کنید (یا `VOIP_RECORDING_KEY` تازه) و در سانترال به‌روز کنید |

## ۷. آنچه برنامه خودش انجام می‌دهد

- هدرهای CSP، HSTS، `X-Frame-Options`، `nosniff`، `Referrer-Policy` روی همهٔ پاسخ‌ها.
- نشست سمت سرور (خروج واقعی، ۴ ساعت بی‌کاری، ۱۲ ساعت مطلق)، قفل ورود برای هر نشانی و هر حساب، سیاست رمز، bcrypt با هزینهٔ ۱۲.
- ثبت ورود ناموفق، درخواست بدون دسترسی و دریافت انبوه در گزارش فعالیت (فقط افزودنی) و هشدار به مدیر کل هنگام تکرار.
- امضا، مهر، شمارهٔ نامه و نام امضاکننده سمت سرور محافظت می‌شود؛ فایل ارسال‌شده قابل جایگزینی نیست.
- خروجی CSV/اکسل در برابر سلول‌های فرمول‌دار امن است؛ مبلغ پیش‌فاکتور سمت سرور از روی اقلام محاسبه می‌شود.
